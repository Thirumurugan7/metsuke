Everything you need to watch an agent work

The editor and the agent share one window, one project, and one browser.

◫ A preview Claude can drive

An embedded browser pointed at your dev server. Claude navigates, clicks, types and screenshots it through the DevTools Protocol — real trusted input, not .click() — so it tests what you actually ship.

⌖ Point at what's wrong

Click any element in the preview and write a note. It reaches Claude with the exact CSS selector attached, so it never has to guess which button you meant.

⑂ Real git, not a summary

Status, staged and unstaged diffs, branches, push and pull, history. It shells out to git, so your hooks, credential helpers and SSH config behave exactly as they do in your terminal.

▤ Terminals that survive

As many Claude sessions and shells as you want, in tabs. Reloading the window reattaches to the running processes and replays their scrollback instead of starting over.

🔔 Told when Claude needs you

Permission requests and idle waits reach you through a pop-up that floats above every app, an OS notification, a sound, or a Telegram message to your phone.

⚓ Ports, found for you

Dev servers you start appear automatically, flagged and sorted first. System daemons and the editor's own ports are filtered out so you never preview a database by mistake.

How the preview works

Claude gets browser tools natively — no extension, no configuration, no per-action approval prompts.

Open a folder

A Claude session starts in it, already wired to the preview. Optionally it begins by walking the whole project and reporting what it found.

Claude edits

The tree and git panel update as it works. Files you have open refresh in place without losing your cursor.

Claude tests

It loads your dev server in the preview, fills forms, walks each flow, and reads the console and network after every step.

You get a report

Screens visited, flows passed and failed, and every problem with the console or network evidence behind it.

claude (your terminal) → MCP server → loopback bridge → Electron main → CDP → preview pane
The preview is isolated. It runs in its own session with an empty cookie jar, holds none of your logins, and cannot reach the editor or your filesystem. That isolation is exactly what makes it safe to hand Claude unrestricted control of it.

Builds are not code-signed yet. On macOS, right-click the app and choose Open the first time, or run xattr -dr com.apple.quarantine "/Applications/Open Claude.app". On Windows, SmartScreen may warn — choose More info, then Run anyway. On Linux, make the AppImage executable with chmod +x.
You'll need Claude Code installed and on your PATH — the editor runs the real claude CLI in its terminal. Everything else works without it.
