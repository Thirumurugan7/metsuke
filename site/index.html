Preview

A browser it can actually use

The preview pane runs your dev server. Claude navigates it, clicks, types and screenshots it through the DevTools Protocol, so the events carry isTrusted and hit the same handlers a real person would. It reads the console and the network log off the same page you are staring at.

That pane is sandboxed in its own session with an empty cookie jar. None of your logins, no reach into the editor or your files. Which is exactly why it can be handed over without a permission prompt every three seconds.

UI audit

It tests everything, not just the happy path

Kick off an audit and Claude maps every screen it can reach, then grinds through the list. Fills each form with real values and submits. Retries with a broken email and an empty required field to see whether your app actually says no. Clicks the buttons that do not submit. Checks the console after every single step.

You get the screens it reached, pass or fail per flow, and the console and network evidence behind every failure. It also tells you what it could not get into, instead of pretending it checked.

PASS /signup form submits, redirects to /welcome
PASS /signup empty email gets rejected
FAIL /checkout "Apply code" does nothing
POST /api/coupon → 500
FAIL /settings no way back to the app
SKIP /admin needs a login I do not have

The rest of the kit

The stuff you would immediately leave for if it was missing.

Actual git

Status, staged and unstaged diffs, branches, push, pull, history. It shells out to the real git binary, so your hooks, credential helpers and SSH config behave exactly like they do in your terminal.

Terminals that survive

As many Claude sessions and shells as you want, in tabs. Reload the window and it reattaches to the running processes and replays the scrollback. Nothing dies.

Alerts that reach you

When Claude needs permission, a card floats over every other app on whichever screen your cursor is on. Or your notification centre, a sound, or straight to Telegram.

Ports, found for you

Dev servers you start show up on their own, flagged and sorted first. Databases and system daemons get filtered out so you never preview Postgres by accident.

Monaco editing

The editor out of VS Code, with per tab undo history. Files the agent rewrites under you refresh in place and keep your cursor exactly where it was.

Quick open

⌘P and fuzzy matching that actually weights filenames over directories. Project search jumps straight to the matching line.

You need Claude Code on your PATH. The editor runs the real claude CLI in its terminal. Everything else works fine without it.

Builds are not notarised yet, so macOS will stop you the first time. It says Apple could not verify the app is free of malware. Nothing is wrong with the download. Open System Settings, Privacy and Security, scroll to the bottom and hit Open Anyway. Or run xattr -dr com.apple.quarantine "/Applications/Metsuke.app" once and it will open normally after that. Right clicking and choosing Open used to work and no longer does: macOS 15 removed that shortcut for apps like this one. Windows SmartScreen complains once. On Linux, chmod +x the AppImage.

Usage reporting is off until you answer the question on first run. If you say yes it sends counts: launches, version and OS, whether Claude Code was found, which features you use, and crashes with the stack trace from our own code. Never your code, your prompts, your terminal output, your file paths or your project names, and nothing that identifies you. Both answers are one click, and Settings changes your mind later.

No account, no analytics service, no crash reporting service. The only other request it makes by itself is an update check against GitHub, which is also a switch. Everything else that leaves your machine is something you did: the claude CLI talking to Anthropic as it always does, whatever you load in the preview, and a Telegram notification if you set one up with your own bot token.

The preview hands Claude real control of the page. It reads the DOM, runs JavaScript in it, clicks and types, and reads the console. It sits in an isolated session with its own cookie jar and cannot touch your browser, but anything you log into inside the pane stays logged in, and anything on screen can reach the model. The README spells out the whole boundary.
